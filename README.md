# Система учета материалов ИП

Приложение для индивидуального предпринимателя, который учитывает материалы
для ремонтных работ. Объектная модель и консольный интерфейс из ПР3 дополнены
базовым веб-интерфейсом на Django в рамках практической работы №5.

## Возможности

- добавление и просмотр материалов;
- поиск по названию, сортировка и отбор по категории;
- расчет стоимости, остатка и недостающего количества;
- оформление поступления и расхода;
- отмена операций с восстановлением остатка;
- просмотр истории и статистики запасов;
- хранение материалов и операций в отдельных JSON-файлах.
- просмотр материалов и операций в браузере;
- отдельные страницы объектов с динамическими URL и обработкой HTTP 404;
- единая навигация и адаптивное оформление на Bootstrap 5.

## Веб-интерфейс ПР5

Веб-часть читает те же объекты `Material` и `Operation` из JSON-файлов, что и
консольное приложение. Django ORM и формы на этом этапе не используются.

| Страница | URL | Назначение |
| --- | --- | --- |
| Главная | `/` | описание проекта и сводка запасов |
| Материалы | `/materials/` | список материалов из `data/materials.json` |
| Материал | `/materials/<id>/` | карточка материала или ответ HTTP 404 |
| Операции | `/operations/` | история движения материалов |
| Операция | `/operations/<id>/` | карточка операции или ответ HTTP 404 |

Маршруты распределены по Django-приложениям `homepage`, `materials_web` и
`operations_web`. Имена веб-приложений не совпадают с именами модулей
`materials.py` и `operations.py`, поэтому консольная часть продолжает работать
без изменения импортов.

## Объектная модель

### `Material`

Материал на складе ИП. Атрибуты: `id`, `name`, `price`, `quantity`, `unit`,
`category`.

Основные методы:

- `calculate_cost()` - расчет стоимости количества;
- `is_available()` - проверка наличия;
- `remaining_after()` - расчет остатка без изменения объекта;
- `receive()` и `spend()` - изменение складского остатка;
- `from_data()` и `to_data()` - преобразование JSON-данных;
- `__str__()` - строковое представление материала.

### `Operation`

Поступление или расход материала. Атрибуты: `id`, `material`, `kind`,
`quantity`, `date`, `note`, `cancelled`.

Основные методы:

- `cancel()` - отмена операции и восстановление остатка;
- `from_data()` и `to_data()` - преобразование JSON-данных;
- `__str__()` - строковое представление операции.

`Operation` хранит ссылку на объект `Material`, а не только его идентификатор.
Это композиция объектов предметной области. При сохранении ссылка преобразуется
в `material_id`, а при загрузке восстанавливается по коллекции материалов.

Функции поиска, сортировки, фильтрации и статистики работают с коллекциями
объектов. Ввод, меню и файловые операции остались отдельными функциями, потому
что не относятся к поведению одного конкретного объекта.

Инкапсуляция проявляется в методах изменения остатка и отмены операции.
Полиморфизм демонстрирует единый вызов `str(object)` для `Material` и
`Operation`. Искусственное наследование не используется: операция не является
разновидностью материала, поэтому между сущностями применена композиция.

## Хранение данных

`data/materials.json` содержит массив данных материалов:

```json
[
  {
    "id": 1,
    "name": "Краска",
    "price": 500,
    "quantity": 8,
    "unit": "л",
    "category": "Отделка"
  }
]
```

`data/operations.json` содержит отдельный массив операций:

```json
[
  {
    "id": 1,
    "material_id": 1,
    "kind": "expense",
    "quantity": 2,
    "date": "2026-09-25",
    "note": "Кухня",
    "cancelled": false
  }
]
```

При запуске JSON преобразуется в `list[Material]` и `list[Operation]`.
После загрузки `operation.material` ссылается на объект из коллекции материалов.
Перед сохранением объекты преобразуются в обычные структуры JSON. Поврежденный
файл не перезаписывается, запись выполняется через временные файлы.

## Правила операций

- название, единица и категория обязательны;
- цена и начальное количество неотрицательны;
- количество операции должно быть больше нуля;
- расход не может превышать остаток;
- повторная отмена запрещена;
- отмененное поступление нельзя применить, если материал уже израсходован;
- отмененные записи сохраняются в истории.

## Установка

Требуется Python 3.10 или новее.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

## Запуск веб-приложения

При первом запуске примените служебные миграции Django:

```powershell
.\.venv\Scripts\python.exe manage.py migrate
.\.venv\Scripts\python.exe manage.py runserver
```

После запуска откройте `http://127.0.0.1:8000/`.

Системная проверка Django выполняется командой:

```powershell
.\.venv\Scripts\python.exe manage.py check
```

## Запуск консольного приложения

```powershell
.\.venv\Scripts\python.exe main.py
```

## Проверка

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m flake8
```

Тесты проверяют создание объектов, методы и `__str__`, операции над
коллекциями, связь `Operation` с `Material`, отмену, JSON-преобразования,
ошибочный ввод, полный сценарий меню, Django-маршруты, содержимое страниц и
обработку несуществующих идентификаторов с кодом HTTP 404.

## Текущее состояние

ПР5 реализует отображение данных предметной области через HTTP, URL-маршруты и
view-функции. Создание и изменение объектов в браузере пока не предусмотрено:
данные продолжают храниться в JSON, а операции записи доступны в консольном
интерфейсе. Перенос данных в Django ORM, шаблоны и веб-формы относятся к
следующим практическим работам.

## Демонстрационный сценарий

1. Добавить материал: краска, 500 руб., 10 л, категория «Отделка».
2. Найти материал, отсортировать список и отобрать категорию.
3. Рассчитать потребность в 12 л: не хватает 2 л на 1000 руб.
4. Оформить поступление 5 л, затем расход 3 л.
5. Показать историю и отменить расход.
6. Завершить программу, запустить снова и проверить восстановление объектов.

Материалы курса Яндекс Практикума выполняются в личном учебном аккаунте и не
могут быть подтверждены содержимым этого репозитория.
